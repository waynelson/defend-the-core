# M0 spike results

Server: a dedicated Linux BDS 1.26.52 managed by Crafty, add-on 0.1.x,
`@minecraft/server` 2.10.0. All tests were driven from the BDS console with
`/scriptevent`, with no player online. Chunks were held loaded by a ticking area
`dtc_core` (circle, radius 4 chunks, around 8 0 8).

## Answered

| Spec verify item | Result | Evidence |
| --- | --- | --- |
| `/scriptevent` works from the BDS console | **Yes.** `sourceType` is `Server`. | `ack` for every action |
| Message length limit | **2048 characters.** Longer messages are rejected by the engine (`Message length exceeds (2048) character limit!`) and never reach the script. | echo test: 1000 ok, 4000 rejected |
| Script console output reaches BDS stdout | **Yes, once `content-log-console-output-enabled=true`.** `console.log`/`info` print as `INFO [Scripting] …`, `warn` as `WARN [Scripting] …`. Off by default. | ping test |
| Mobs path to a dummy entity target | **Yes.** `core_only` zombies crossed ~40 blocks of real terrain and meleed `dm:core` until it died. | core 200 → 0, `game_over` |
| Mobs can melee an entity inside a solid block | **Yes.** Core entity inside a beacon took 7 zombie hits in 40 s. The on-top fallback isn't needed. | test E |
| Skeletons shoot the core | **Yes, poorly.** 3 core hits against 32 arrows into terrain in 45 s at ~14 blocks. Arrows pass the damage sensor (`by: dm:skeleton`, `projectile: minecraft:arrow`). | test B |
| Blocked path → idle at nearest reachable point | **Yes.** With the core in a 7×7×7 cobblestone shell, all zombies stopped against the wall at 4–4.7 blocks from center, moving ≤ 0.2 blocks/s, and did no damage. They all chose the same (east) face regardless of approach. | test C |
| `projectileHitBlock` reports the shooter | **Yes.** `event.source` is the skeleton; `getBlockHit().block` gives the block. `siege_arrow` can be built as specified. | `arrow_hit_block` events |
| `follow_range` 64 | Targets acquired from 40 blocks; no perf problems seen with 8 mobs. Not stress-tested. | |

## Found along the way

- **Friendly fire starts infighting.** Vanilla `hurt_by_target` makes skeletons retaliate against each other's stray arrows. Fixed by filtering `dm_attacker` out of `hurt_by_target`.
- **Stable 2.10.0 has no `Entity.target`.** Scripts can't read what a mob is targeting. Stuck detection must use position and distance only (the spec already assumes this).
- **Crafty keeps a short output buffer** (`max_log_lines`), and BDS has no log file path in Crafty. The DM plugin must consume the live output stream, not poll the logs API.
- `minecraft:pushable_by_entity` / `pushable_by_block` take no `value` in 1.26.50. Omit them to make an entity unpushable.
- Skeleton `ranged_attack` fires without line of sight, so arrows hit walls between skeleton and core. That is the trigger `siege_arrow` needs.

## Gate decision (draft)

- **Entity JSON**: targeting (core first, players by radius), movement, melee and ranged attacks, damage filtering on the core.
- **Script**: everything that changes blocks (damage map, breach modules), stuck detection, core registration, spawning, game state, reporting.
- Protocol messages must stay well under 2048 characters including the action id. One spawn group per message is fine.
